# 08 · 反向操作可行性矩阵

> **本篇是 skill 反向操作设计的最终决策依据。**
> 横轴 = 插件全部用户可见能力，纵轴 = "能否纯外部命令行驱动 / 需要 IDE state / 完全无法外部驱动"，并给出脚本伪代码与 MVP 推荐。
> 所有命令前提：`adb` 已能 `adb shell` 到目标设备，被调试 App 已集成 `codelocator-sdk` 且 `CodeLocatorProvider` 注册成功（详见 06 文档）。

---

## 1. 三档可行性等级

| 等级 | 含义 |
|------|------|
| 🟢 **可外部驱动** | 在 skill 端用 `adb` 即可复刻，无需 IDE 进程；最多需要"先 grab 一次取 memAddr 等 stateful 信息" |
| 🟡 **依赖抓取上下文 / SDK 状态** | 能外部驱动但需要一些前置：先 grab、SDK 端某些配置、辅助 APK 等；skill 可承担这些前置 |
| 🔴 **无法外部驱动** | 完全依赖 IDE PSI / VirtualFile / 工程目录 / ToolWindow UI 状态，反向 skill 不应承诺 |

---

## 2. 大矩阵

### 2.1 抓取与数据获取

| 功能 (用户视角) | 实际 Action | 通道 | 等级 | 卡点 / 备注 |

| 抓取并停止动画 | `GrabViewWithStopAnimAction` | 同上 + `KEY_STOP_ALL_ANIM` | 🟢 | 见 §3.2 |
| 拉取应用沙盒文件树 | 文件 Tab 加载 | `ACTION_DEBUG_FILE_INFO` | 🟢 | 见 §3.3 |
| 取 View Data（自定义数据） | `GetViewDataAction` | `ACTION_CHANGE_VIEW_INFO + GetDataModel` | 🟡 | 需要 grab 拿 memAddr |
| 取 View 反射类信息 | `GetViewClassInfoAction` | `ACTION_CHANGE_VIEW_INFO + GetViewClassInfoModel` | 🟡 | 需要 memAddr |
| 取 Intent 信息 | `GetIntentDataAction` | `ACTION_CHANGE_VIEW_INFO + GetIntentModel`（type=Activity/Fragment） | 🟡 | 需要 Activity 的 memAddr |

## 3. "能外部驱动" 的脚本伪代码

以下命令在 macOS / Linux + `adb` 直接可执行。占位符：`<PKG>` 业务 App 包名，`<SERIAL>` 设备序列号（可选）。

> ⚠ **base64 编码必须是 URL_SAFE / NO_PADDING / NO_WRAP**（对齐 SDK `SmartArgs.decode` 用的 `Base64.DEFAULT_FLAGS`，详细解释见 `03-ADB命令与BroadcastAction协议.md §4` 开头 ⚠ 块）。下面所有 `base64 | tr -d '\n=' | tr '+/' '-_'` 就是这一约定的 shell 实现。

### 3.1 抓取一次界面（MVP 推荐之一）

```bash
PKG=com.xxx.yyy
ADB="adb"  # 或 "adb -s $SERIAL"

# 1. 健康检查 + 取 SDK 版本
HEALTH=$($ADB shell "content query --uri content://${PKG}.CodeLocatorProvider")
echo "$HEALTH"  # 期望 CodeLocatorVersion=..., AsyncBroadcast=..., AsyncResult=...

# 2. 抓取广播
ARGS=$(printf '{"codeLocator_save_to_file":"true","codeLocator_need_color":"true"}' | base64 | tr -d '\n=' | tr '+/' '-_')
RESP=$($ADB shell "am broadcast -a com.bytedance.tools.codelocator.action_debug_layout_info \
    --es codeLocator_shell_args '$ARGS'")

# 3. 取设备端结果文件路径
FP=$(echo "$RESP" | grep -oE 'data="[^"]+"' | sed -E 's/.*data="(FP:)?([^"]+)"/\2/')
[ -z "$FP" ] && { echo "no FP, maybe app not in foreground or SDK not init"; exit 1; }

# 4. 拉数据文件
$ADB pull "$FP" /tmp/cl_data.txt

# 5. 解码：SDK 写文件用的也是 URL_SAFE / NO_PADDING base64，先转回标准 base64 + 补 padding 再 -d
tr -d '\n' < /tmp/cl_data.txt | tr '_-' '/+' \
  | awk '{ pad=(4-length%4)%4; for(i=0;i<pad;i++) $0=$0"="; print }' \
  | base64 -d | gunzip > /tmp/cl_data.json

# 6. 抓屏
$ADB shell screencap -p > /tmp/cl_screen.png

# 7.（可选）按 .codeLocator 二进制布局组装历史文件
# tagLen(4) + "CodeLocator" + verLen(4) + "skill-reverse" + jsonLen(4) + json + png_bytes
```

> ⚠ 注意 1：`echo -n` 在不同 shell 行为不一致，**推荐用 `printf %s`**。
> ⚠ 注意 2：Android 10+ 设备 `am broadcast` 的 `data="..."` 字段中若 path 含特殊字符可能被 quote，正则要按需调整。

### 3.2 抓取 + 停止动画

```bash
ARGS=$(printf '{"codeLocator_save_to_file":"true","codeLocator_need_color":"true","codeLocator_stop_all_anim":"2000"}' \
    | base64 | tr -d '\n=' | tr '+/' '-_')
$ADB shell "am broadcast -a com.bytedance.tools.codelocator.action_debug_layout_info \
    --es codeLocator_shell_args '$ARGS'"
# 注意：SDK 内会 Thread.sleep(2000) 后才回 result，命令同步等
```

### 3.3 拉沙盒文件树

```bash
ARGS=$(printf '{"codeLocator_save_to_file":"true"}' | base64 | tr -d '\n=' | tr '+/' '-_')
RESP=$($ADB shell "am broadcast -a com.bytedance.tools.codelocator.action_debug_file_info \
    --es codeLocator_shell_args '$ARGS'")
FP=$(echo "$RESP" | grep -oE 'FP:[^"]+' | sed 's/^FP://')
$ADB pull "$FP" /tmp/cl_files.txt
# 同 §3.1 step 5：转回标准 base64 + 补 padding 再 -d
tr -d '\n' < /tmp/cl_files.txt | tr '_-' '/+' \
  | awk '{ pad=(4-length%4)%4; for(i=0;i<pad;i++) $0=$0"="; print }' \
  | base64 -d | gunzip | jq .
# data.data 是 WFile 树
```

### 3.4 发 Schema（MVP 推荐之一）

```bash
SCHEMA="snssdk1128://feed"

# 优先 am start
ERR=$($ADB shell "am start -d '$SCHEMA'" 2>&1 | grep -i Error)
if [ -n "$ERR" ]; then
    # 兜底广播
    ARGS=$(printf '{"codeLocator_schema":"%s","codeLocator_save_to_file":"true"}' "$SCHEMA" | base64 | tr -d '\n=' | tr '+/' '-_')
    $ADB shell "am broadcast -a com.bytedance.tools.codelocator.action_process_schema \
        --es codeLocator_shell_args '$ARGS'"
fi
```

### 3.5 改 View 属性（先 grab）

```bash
# 1. 假设 cl_data.json 已存在，找到目标 View 的 memAddr
MEMADDR=$(jq -r '.data.b7.cj[0].a[0].af' /tmp/cl_data.json)  # 示例路径，按需改
ITEM_ID=$(printf '%d' "0x$MEMADDR")

# 2. 构造 OperateData JSON
EDIT='{"type":"V","itemId":'"$ITEM_ID"',"dataList":[{"type":"T","value":"Hello from skill"}]}'

# 3. 嵌套到 KEY_CHANGE_VIEW
WRAPPER=$(jq -n --arg cv "$EDIT" '{codeLocator_change_view: $cv, codeLocator_save_to_file: "true"}')
ARGS=$(printf %s "$WRAPPER" | base64 | tr -d '\n=' | tr '+/' '-_')

$ADB shell "am broadcast -a com.bytedance.tools.codelocator.action_change_view_info \
    --es codeLocator_shell_args '$ARGS'"
```

### 3.6 模拟点击拿命中链

> ⚠ **此命令默认不会被任何 receiver 接收**：SDK 内置 `IntentFilter` 未注册 `ACTION_MOCK_TOUCH_VIEW`（`CodeLocator.java:397-405` 与 06 §2 已说明），需要业务方通过 `ICodeLocatorProcessor.providerRegisterAction()` 自行把它加进去。下面只展示协议格式：

```bash
ARGS=$(printf '{"codeLocator_mock_click_x":"540","codeLocator_mock_click_y":"1200","codeLocator_save_to_file":"true"}' \
    | base64 | tr -d '\n=' | tr '+/' '-_')
$ADB shell "am broadcast -a com.bytedance.tools.codelocator.action_mock_touch_view \
    --es codeLocator_shell_args '$ARGS'"
```

### 3.7 切布局边界

```bash
$ADB shell setprop debug.layout true
ARGS=$(printf '{"codeLocator_tools_command":"command_update_activity"}' | base64 | tr -d '\n=' | tr '+/' '-_')
$ADB shell "am broadcast -a com.bytedance.tools.codelocator.action_use_tools_info \
    --es codeLocator_shell_args '$ARGS'"
```

### 3.8 设备端 ignore 列表写入（关闭某些 Toast/Dialog 监控）

```bash
# Action=add 时 KEY_DATA 是要忽略的 className，KEY_CONFIG_TYPE 是分类
DATA="com.xxx.yyy.LoginActivity"
ARGS=$(printf '{"codeLocator_action":"add","config_type":"activity_ignore","codeLocator_data":"%s","codeLocator_save_to_file":"true"}' "$DATA" \
    | base64 | tr -d '\n=' | tr '+/' '-_')
$ADB shell "am broadcast -a com.bytedance.tools.codelocator.action_process_config_list \
    --es codeLocator_shell_args '$ARGS'"
```

`config_type` 取值：`activity_ignore / view_ignore / popup_ignore / dialog_ignore / toast_ignore / enable_codelocator / enable_codelocator_lancet`。

## 4. "需要 IDE state" 的功能：卡点详解

| Action | 卡在哪里 | 反向 skill 替代方案 |
|--------|----------|---------------------|
| `FindViewAction` | 需要 IDE PSI 在 module 内搜 `findViewById(R.id.xxx)`；只有 `idStr` 不够，要解析整个工程 R.java | 用户自行在编辑器搜（skill 仅能输出 idStr） |
| `FindClickListenerAction` | 依赖 `clickTag`（Lancet 插桩字符串："com.xxx.A$1.onClick:42"），需要 IDE 解析这个字符串定位 PSI | skill 可输出 clickTag 字符串供用户自己搜 |
| `FindXmlAction` | 依赖 `xmlTag`（"layout/main:23"），需要 IDE 打开对应 layout XML 跳行 | skill 输出 tag |
| `OpenClassAction` | IDE JumpToClassName | skill 不行 |
| `ViewHolderAction` | 同上 + 需要 ViewHolder 类名 | 同上 |
| `OpenActivityAction` | 需要 `startInfo`（启动栈），解析后 IDE 跳到 startActivity 调用处 | skill 输出 startInfo 文本 |
| `AddSourceCodeAction` | 改工程 `build.gradle` 加 module 依赖 | 不行 |
| `InstallApkMenuAction` (Project 右键) | 需要 IDE 文件选中状态 | skill 可让用户传 APK 路径 → `adb install` |
| `SearchInWebAction` | 编辑器 selection + 工程 git url | 不行 |
| `Mark/Fold/TopItem` 等 UI 标注 | 工具窗 UI 内部状态 | 不行 |
| `NewWindow` / `DiffMode` | 多工具窗实例 | 不行 |
| `Feedback` | 公司内部反馈接口 | 不行 |
| `Update` | IDE plugin manager | 不行 |

## 5. Skill 反向操作 MVP 推荐（优先级 Top 3）

> 选择标准：**高频 + 通用 + 不需要繁琐前置 + 不需要 IDE PSI**。

### 🥇 1) Grab View（抓取并自动落盘 `.codeLocator`）

**理由**：
- 用户最高频的需求（IDE 工具栏第一个按钮）。
- 完全可以 `adb` 复刻，命令链清晰（见 §3.1）。
- 落盘后 skill 现有 `parse-codelocator-file.ts` 即可解析，闭环完整。
- 没有 IDE 依赖、不需要 memAddr 等 stateful 信息、不需要辅助 APK。

**最小验证步骤**：
1. `content query` 健康检查
2. `am broadcast -a ACTION_DEBUG_LAYOUT_INFO` + Base64 JSON args
3. `adb pull` + Base64+GZIP 解码
4. `adb shell screencap -p` 拿 PNG
5. 按 `.codeLocator` 二进制布局组装文件，写到 `~/.codeLocator_main/historyFile/`

**预计 LOC**：100-200 行 TypeScript。

---

### 🥈 2) Send Schema（下发 Deep Link）

**理由**：
- 调试时高频：测试某个页面入口、复现 schema 路由 bug。
- 一行 `am start -d` 几乎所有场景能解决，只在 Schema 走自定义协议时才需要 `ACTION_PROCESS_SCHEMA` 兜底。
- 不依赖任何抓取上下文，纯命令。
- 用户可以直接传 schema 字符串，skill 透传 + 加双重 fallback。

**最小验证步骤**：见 §3.4。

**预计 LOC**：30-60 行。

---

### 🥉 3) 点击链路追踪（Find Click View）

**理由**：
- 调试卡顿、定位某次触摸命中哪个 View 是常见诉求。
- `ACTION_GET_TOUCH_VIEW` 不需要 memAddr，使用门槛低。
- 返回 `TouchViewResponse.data` 是 View Address 列表（字符串），skill 可直接显示；如果已有最近一次 `.codeLocator`，还能反查这些 memAddr 对应的 className/idStr。
- 完美利用 skill 已有的 `.codeLocator` 解析能力，"反向 + 读现有数据" 联动。

**最小验证步骤**：
1. （可选）先 grab 拿 view 树
2. `am broadcast -a ACTION_GET_TOUCH_VIEW`
3. 解码 `TouchViewResponse`，得到 memAddr 数组
4. 对照 grab 数据找出对应 View 信息

**预计 LOC**：60-100 行。

---

### 退选理由（为什么没选 EditView / FileOperate）

- **EditView**：需要先 grab 拿 memAddr → 用户从 grab JSON 里挑 View → 构造 `OperateData` JSON 嵌套 Base64 → 改起来心智模型重，且改完没截图回执不直观。可作为 V2 功能。
- **FileOperate**：用户可能更习惯直接 `adb shell run-as <pkg> ls/cat`，skill 套一层 SDK broadcast 收益有限，除非用户场景明确需要"应用沙盒可视化文件树"。可作为 V2 功能。
- **打开 / 关闭布局边界 / 代理 / 触摸点**：每个是一行 `setprop` / `settings`，价值不如先把核心抓取做好。

## 6. MVP 之后的扩展路线（V2 / V3）

| 优先级 | 功能 | 价值 | 难点 |
|--------|------|------|------|
| V2.1 | EditView（最少支持改 visibility / text） | 调试效率 | memAddr 时效性，需要在 skill 内缓存最近 grab 结果并校验 |
| V2.2 | FileOperate（pull / push / delete） | 工具替代 | API 30+ 路径动态、文件树需要再次抓取 |
| V2.3 | 抓 View 截图（分层 / Foreground / Background） | 视觉差异调试 | 同 EditView memAddr，再加图像处理 |
| V2.4 | 模拟点击（坐标 → 命中链） | 自动化 | **前置：SDK 内置 IntentFilter 未注册此 action**（CodeLocator.java:397-405），必须先让业务方通过 `ICodeLocatorProcessor.providerRegisterAction()` 注册，否则 broadcast 发出去无人接 |

## 7. 风险与边界

1. **memAddr 时效**：进程重启或 GC 后失效，EditView/Get*Data 类操作都会失败。skill 必须在每次调用前先 grab 一次，或者明确告诉用户"上次 grab 的 memAddr 可能已经无效"。
2. **App 在后台**：SDK `unregisterReceiver`，所有 broadcast 都会"看起来发出但 data 为空"。skill 应在 grab 前做"前台进程"检测（dumpsys activity activities）。
3. **多设备**：插件用 `getCurrentDevice(project)`，skill 端要让用户指定 `adb -s <serial>` 或自动选第一台。
4. **大 payload 不走文件**：广播 `data="..."` 会被 stdout 截断；**反向操作永远带 `KEY_SAVE_TO_FILE=true`**。
5. **异步广播**：如果设备端开了 `AsyncBroadcast`，`data=` 会为空，必须通过 `content query` 轮询 `AsyncResult` 字段。
6. **API 等级差异**：SDK 在 API 30+ 写文件到 ExternalCacheDir，路径含 `<pkg>`；< 30 走 `/sdcard/Download/`。skill 不要硬编码路径，要从 broadcast `FP:<path>` 字段拿。
7. **Base64 / GZIP / JSON 三件套**：每一层都可能因为编码 / 转义出问题。封装一个 helper：`runBroadcast(action, argsObj) → BaseResponse JSON`。
8. **跨 Action 的 `data` 字段类型不一致**：`StringResponse.data: String`、`ApplicationResponse.data: WApplication`、`OperateResponse.data: ResultData`、`TouchViewResponse.data: List<String>`……skill 要按 Action 决定如何解码。

## 8. 推荐的 skill 反向操作命令骨架（TypeScript 伪代码）

```ts
interface RunBroadcastOpts {
  action: string;               // e.g. ACTION_DEBUG_LAYOUT_INFO
  args?: Record<string, string>; // 不含 KEY_SHELL_ARGS 外壳
  saveToFile?: boolean;          // 默认 true
  async?: boolean;               // 默认 false
  serial?: string;
}

async function runBroadcast(opts: RunBroadcastOpts): Promise<BaseResponse> {
  const args = { ...(opts.args ?? {}) };
  if (opts.saveToFile !== false) args["codeLocator_save_to_file"] = "true";
  if (opts.async) args["codeLocator_save_async"] = "true";

  // URL_SAFE / NO_PADDING base64 编码（Node 16+ "base64url" 内置等价 URL_SAFE | NO_PADDING）
  // 对齐 SDK SmartArgs.decode 用的 Base64.DEFAULT_FLAGS，详见 03 §4 ⚠
  const b64 = Buffer.from(JSON.stringify(args), "utf-8").toString("base64url");
  const cmd = `am broadcast -a ${opts.action} --es codeLocator_shell_args '${b64}'`;
  const stdout = await adbShell(cmd, opts.serial);

  // 1) 解 FP:<path>
  const fpMatch = stdout.match(/data="(FP:[^"]+)"/);
  let payload: string;
  if (fpMatch) {
    const path = fpMatch[1].slice(3);
    const localTmp = `/tmp/cl_${Date.now()}.txt`;
    await adbPull(path, localTmp, opts.serial);
    payload = fs.readFileSync(localTmp, "utf-8");
  } else {
    const dataMatch = stdout.match(/data="([^"]+)"/);
    if (!dataMatch) throw new Error("no broadcast result");
    payload = dataMatch[1];
  }
  // 2) Base64URL → GZIP → JSON（SDK 写回的 payload 同样是 URL_SAFE / NO_PADDING）
  const json = await gunzip(Buffer.from(payload, "base64url"));
  return JSON.parse(json.toString("utf-8")) as BaseResponse;
}
```
